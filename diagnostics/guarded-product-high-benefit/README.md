# Original matched benefit trial

These tools restore the accepted stock and guarded-product executable pair and
run one original A1/B1/B2/A2 experiment. The original observer, numerical
workload, three repeats per family/slot, reader, comparator, launcher and all
twenty interval/stage plus two inclusive API conditions remain unchanged.

Restore these files under `out/guarded-product-high-benefit` in the canonical
Sirius checkout, preserving the nested `benefit` directory. Run from the
repository root using the existing `linux-gcc` preset products and the local
control/archive evidence named in `prepare.py`. Ignored binary evidence is not
backed up by this source tag. The checkout must remain clean at its stated
revision. Both diagnostic roots must be absent before preparation.

```sh
python3 -B out/guarded-product-high-benefit/prepare.py
python3 -B out/guarded-product-high-benefit/prove_reuse.py
python3 -B out/guarded-product-high-benefit/benefit/run_sequence.py
python3 -B out/guarded-product-high-benefit/benefit/compare_software.py
```

The fixed trial keeps the original 300-second / 4-GiB sampled RSS / 2-GiB
reserve governors, CORE=0, FSIZE=64 MiB and device allocation cap. The reader
requires complete readback digests, ordered available timestamps and actual
command/module/binding records in every slot. Forward and reverse decisions
remain separate. Do not restart a partial sequence, pool orders or retry a
rejected trial.

A benefit pass is a prerequisite for production implementation. It does not
adopt the private shader policy, qualify rendered frames, or establish full
science, native/platform or release readiness. Preservation and cleanup helpers
require terminal owners, recorded disposition, recoverable inputs, exact
archive/source recovery and fresh scoped consumer checks for the two roots.
